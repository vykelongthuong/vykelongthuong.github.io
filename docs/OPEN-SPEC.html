1. Hiểu thật đơn giản

Claude CLI là công cụ để bạn trò chuyện với Claude ngay trong terminal, rồi nhờ Claude đọc code, sửa code, tạo file, chạy lệnh và hỗ trợ lập trình.

OpenSpec là công cụ giúp Claude làm việc có kế hoạch hơn. Thay vì bạn nói “thêm tính năng này đi” rồi Claude tự đoán, OpenSpec bắt Claude viết ra trước:

  • Muốn làm gì?
  • Vì sao cần làm?
  • Thiết kế dự kiến ra sao?
  • Cần sửa những phần nào?
  • Danh sách việc cần làm gồm những bước nào?
Nói ngắn gọn: OpenSpec giống như “bản kế hoạch” trước khi cho Claude viết code. Nó giúp giảm lỗi, giảm hiểu nhầm và dễ kiểm tra lại sau này.

Ví dụ đời thường

Nếu bạn thuê thợ sửa nhà, bạn không nên chỉ nói “sửa nhà cho đẹp”. Bạn nên có bản mô tả: sửa phòng nào, màu gì, vật liệu gì, làm xong cần đạt tiêu chuẩn gì. OpenSpec cũng vậy, nhưng áp dụng cho dự án phần mềm.

2. Bạn cần chuẩn bị gì?

Đừng lo nếu bạn chưa biết lập trình nhiều. Bạn chỉ cần hiểu vài khái niệm cơ bản sau:

Khái niệm Hiểu đơn giản
Terminal / Command Prompt Cửa sổ để gõ lệnh cho máy tính.
Project Thư mục chứa toàn bộ code của website/app/phần mềm.
Claude CLI Nơi bạn chat với Claude trong terminal.
OpenSpec Bộ công cụ giúp Claude lập kế hoạch trước khi code.
Spec Bản đặc tả: mô tả tính năng phải hoạt động như thế nào.
Change Một thay đổi cụ thể trong dự án, ví dụ “thêm đăng nhập Google”.

Phần mềm cần có

  • Node.js: nên dùng phiên bản 20.19.0 trở lên.
  • npm: thường đi kèm khi cài Node.js.
  • Claude CLI / Claude Code: công cụ bạn đang dùng để coding.
  • OpenSpec: sẽ cài bằng npm ở bước tiếp theo.

3. Cài đặt từng bước

1

Kiểm tra Node.js

Mở terminal và gõ:

node -v

Nếu hiện ra ví dụ v20.19.0, v21.x, v22.x là ổn. Nếu máy báo không nhận lệnh node, bạn cần cài Node.js trước.

2

Cài OpenSpec

Gõ lệnh sau trong terminal:

npm install -g @fission-ai/openspec@latest

Lệnh này cài OpenSpec trên máy để bạn có thể dùng lệnh openspec.

3

Đi vào thư mục dự án

Ví dụ dự án của bạn nằm ở Desktop:

cd Desktop/ten-du-an-cua-ban
Lưu ý: Bạn phải đứng đúng trong thư mục dự án trước khi chạy OpenSpec. Nếu chạy nhầm thư mục, OpenSpec sẽ tạo file nhầm chỗ.
4

Khởi tạo OpenSpec cho Claude

openspec init --tools claude

Lệnh này sẽ tạo cấu hình để Claude CLI hiểu các lệnh dạng /opsx:propose, /opsx:apply, /opsx:archive.

5

Mở Claude CLI trong dự án

claude

Sau khi vào Claude CLI, bạn bắt đầu gõ các lệnh /opsx.

4. Gõ lệnh ở đâu?

Có 2 nơi khác nhau, người mới rất dễ nhầm:

Nơi gõ Dùng để làm gì? Ví dụ
Terminal bình thường Cài đặt, kiểm tra, khởi tạo OpenSpec. npm install -g @fission-ai/openspec@latest
openspec init --tools claude

/opsx:apply
Đừng nhầm: Lệnh bắt đầu bằng openspec thường gõ ở terminal. Lệnh bắt đầu bằng /opsx: gõ trong Claude CLI.

5. Quy trình làm việc dễ nhớ

Với người mới, bạn chỉ cần nhớ quy trình 4 bước này:

/opsx:explore → /opsx:propose → /opsx:apply → /opsx:archive
Bước Dùng lệnh Ý nghĩa dễ hiểu
1 /opsx:explore Nhờ Claude tìm hiểu dự án trước, chưa sửa code.
2 /opsx:propose Nhờ Claude tạo bản kế hoạch/spec cho thay đổi.
3 /opsx:apply Cho Claude bắt đầu sửa code theo kế hoạch.
4 /opsx:archive Hoàn tất thay đổi, lưu lại lịch sử.
Công thức an toàn: Nếu thay đổi lớn, đừng bảo Claude “code luôn”. Hãy dùng /opsx:propose trước để Claude viết kế hoạch cho bạn duyệt.

6. Trọn bộ lệnh /opsx trong Claude CLI

Các lệnh dưới đây được gõ trong Claude CLI, không phải terminal thường.

Nhóm lệnh cốt lõi nên biết

/opsx:explore Phân tích trước

Dùng khi: Bạn chưa hiểu dự án, chưa chắc nên làm thế nào, hoặc muốn Claude đọc code trước.

Lệnh mẫu:

/opsx:explore dự án này đang xử lý đăng nhập như thế nào?
/opsx:explore tôi muốn thêm trang quản lý sản phẩm, hãy phân tích cách làm phù hợp

Kết quả mong đợi: Claude giải thích hiện trạng, đề xuất hướng làm, chưa tạo kế hoạch chính thức và chưa sửa code.

/opsx:propose Tạo kế hoạch

Dùng khi: Bạn đã có ý tưởng muốn thêm/sửa một tính năng và muốn Claude viết kế hoạch rõ ràng.

Lệnh mẫu:

/opsx:propose thêm chức năng đăng nhập bằng Google
/opsx:propose tạo trang dashboard hiển thị doanh thu theo ngày

Kết quả mong đợi: Claude tạo một thư mục thay đổi trong openspec/changes/, thường gồm proposal, design, tasks và spec.

Sau khi chạy /opsx:propose, bạn nên đọc lại kế hoạch trước khi cho Claude code. Nếu sai, yêu cầu Claude sửa spec trước.

/opsx:apply Bắt đầu code

Dùng khi: Bạn đã xem kế hoạch và đồng ý để Claude sửa code.

Lệnh mẫu:

/opsx:apply

Kết quả mong đợi: Claude đọc task, sửa code từng bước, đánh dấu task đã hoàn thành.

Không nên dùng /opsx:apply khi bạn chưa đọc kế hoạch, nhất là với tính năng lớn.

/opsx:sync Đồng bộ spec

Dùng khi: Code đã thay đổi và bạn muốn cập nhật spec chính để phản ánh trạng thái mới của dự án.

Lệnh mẫu:

/opsx:sync

Kết quả mong đợi: Các thay đổi trong spec được đưa vào phần spec chính của dự án.

/opsx:archive Hoàn tất

Dùng khi: Tính năng đã code xong, bạn đã kiểm tra và muốn đóng change lại.

Lệnh mẫu:

/opsx:archive

Kết quả mong đợi: Change được chuyển vào khu vực archive để lưu lịch sử. Đây là bước kết thúc gọn gàng.

Nhóm lệnh mở rộng

Không phải lúc nào cũng cần dùng các lệnh này. Người mới có thể đọc để biết, khi quen hơn hãy dùng.

/opsx:new Tạo nhanh change

Dùng khi: Bạn muốn bắt đầu một change mới theo workflow mở rộng. Một số cấu hình OpenSpec có thể dùng lệnh này để tạo bộ khung ban đầu.

/opsx:new add-product-search

/opsx:continue Tiếp tục việc đang làm

Dùng khi: Bạn đang làm dở một change, đóng Claude hoặc nghỉ giữa chừng, sau đó muốn Claude tiếp tục.

/opsx:continue

Mẹo: Trước khi tiếp tục, có thể nói: “Hãy đọc lại tasks.md và cho tôi biết bước tiếp theo là gì.”

/opsx:ff Fast-forward

Dùng khi: Bạn muốn Claude tiến nhanh qua một số bước trong workflow. Lệnh này phù hợp hơn cho người đã quen.

/opsx:ff
Người mới không cần dùng lệnh này thường xuyên. Hãy dùng workflow chậm nhưng chắc: propose → apply → archive.

/opsx:verify Kiểm tra lại

Dùng khi: Sau khi Claude code xong, bạn muốn kiểm tra code có khớp với spec, design và tasks không.

/opsx:verify

Kết quả mong đợi: Claude rà soát xem còn thiếu task, thiếu test, hoặc làm lệch yêu cầu không.

/opsx:bulk-archive Lưu nhiều change

Dùng khi: Dự án có nhiều change đã xong và bạn muốn archive hàng loạt.

/opsx:bulk-archive

Khuyến nghị: Người mới nên archive từng change bằng /opsx:archive để dễ kiểm soát.

/opsx:onboard Làm quen dự án

Dùng khi: Bạn mới mở một dự án, chưa hiểu code, muốn Claude phân tích tổng quan.

/opsx:onboard

Kết quả mong đợi: Claude giúp bạn hiểu cấu trúc dự án, công nghệ dùng, cách chạy, những phần quan trọng.

7. Lệnh terminal openspec

Các lệnh này gõ ở terminal bình thường, không phải trong Claude chat.

Lệnh Dùng để làm gì? Khi nào dùng?
openspec init --tools claude Khởi tạo OpenSpec cho Claude CLI. Khi mới thêm OpenSpec vào dự án.
openspec list Xem danh sách change/spec. Khi muốn biết đang có những thay đổi nào.
openspec status Xem trạng thái hiện tại của OpenSpec. Khi không chắc change nào đang mở, cái nào đã xong.
openspec validate --all Kiểm tra toàn bộ spec có hợp lệ không. Trước khi commit, trước khi archive, hoặc khi thấy lỗi lạ.
openspec view Xem nội dung spec/change trong terminal. Khi muốn đọc nhanh mà không mở editor.
openspec update Cập nhật OpenSpec hoặc cấu hình liên quan. Khi muốn dùng bản mới hoặc sau khi nâng cấp tool.

Ví dụ dùng terminal

cd Desktop/my-project
openspec status
openspec validate --all

8. Ví dụ thực tế từ đầu đến cuối

Giả sử bạn có một website bán hàng và muốn thêm chức năng tìm kiếm sản phẩm.

Bước 1: Mở terminal, vào dự án

cd Desktop/shop-app

Bước 2: Nếu chưa cài OpenSpec cho dự án

openspec init --tools claude

Bước 3: Mở Claude CLI

claude

Bước 4: Nhờ Claude phân tích trước

/opsx:explore dự án này đang hiển thị danh sách sản phẩm như thế nào? Tôi muốn thêm ô tìm kiếm sản phẩm.

Sau bước này, Claude sẽ đọc code và giải thích. Bạn chưa cho Claude sửa code.

Bước 5: Tạo kế hoạch chính thức

/opsx:propose thêm ô tìm kiếm sản phẩm theo tên, cập nhật kết quả ngay khi người dùng nhập

Sau khi Claude tạo kế hoạch, bạn nên yêu cầu:

Hãy tóm tắt proposal, design và tasks bằng tiếng Việt dễ hiểu. Chưa sửa code.

Bước 6: Nếu kế hoạch chưa đúng, yêu cầu sửa

Sửa lại spec: chỉ tìm kiếm theo tên sản phẩm, chưa cần tìm theo mô tả hoặc danh mục.

Bước 7: Cho Claude code

/opsx:apply

Bước 8: Bảo Claude kiểm tra

Chạy lint, test hoặc build nếu dự án có hỗ trợ. Nếu có lỗi thì sửa.

Bước 9: Kiểm tra lại bằng verify nếu có

/opsx:verify

Bước 10: Hoàn tất

/opsx:archive
Sau quy trình này, bạn có code đã sửa, có kế hoạch lưu lại, có task đã hoàn thành và có lịch sử thay đổi rõ ràng.

9. Mẫu câu lệnh nên dùng

Bạn có thể copy các mẫu dưới đây và đổi nội dung theo dự án của mình.

Khi chưa hiểu dự án

/opsx:explore hãy đọc dự án này và giải thích cấu trúc chính bằng tiếng Việt dễ hiểu cho người mới

Khi muốn thêm tính năng

/opsx:propose thêm chức năng [mô tả tính năng], yêu cầu giải thích rõ proposal, design và tasks bằng tiếng Việt

Khi muốn sửa lỗi

/opsx:propose sửa lỗi [mô tả lỗi], trước tiên hãy tìm nguyên nhân, sau đó đề xuất cách sửa an toàn

Khi muốn Claude chưa code vội

Chỉ phân tích và lập kế hoạch, chưa sửa file, chưa chạy lệnh thay đổi hệ thống.

Khi muốn Claude giải thích dễ hiểu

Giải thích từng bước bằng tiếng Việt đơn giản, giả sử tôi là người mới học lập trình.

Khi muốn kiểm tra trước khi hoàn tất

Hãy so sánh code hiện tại với tasks.md và spec, liệt kê phần nào đã xong, phần nào còn thiếu.

10. Lỗi thường gặp và cách xử lý

1. Gõ /opsx:propose nhưng Claude không hiểu

Nguyên nhân có thể: Bạn chưa chạy openspec init --tools claude, hoặc đang mở Claude ở sai thư mục.

Cách xử lý:

cd duong-dan-den-du-an
openspec init --tools claude
claude

2. Lệnh openspec không chạy

Nguyên nhân có thể: Chưa cài OpenSpec hoặc npm global path chưa đúng.

Cách xử lý:

npm install -g @fission-ai/openspec@latest
openspec --help

3. Lệnh node -v báo lỗi

Nguyên nhân: Máy chưa cài Node.js hoặc cài chưa đúng.

Cách xử lý: Cài Node.js bản mới, sau đó mở lại terminal và chạy lại node -v.

4. Claude sửa code không đúng ý

Nguyên nhân: Spec hoặc yêu cầu ban đầu chưa đủ rõ.

Cách xử lý: Dừng lại, yêu cầu Claude sửa spec/task trước:

Sửa lại spec: [mô tả yêu cầu đúng]. Chưa code tiếp cho đến khi tôi đồng ý.

5. Dự án có nhiều change, không biết đang làm cái nào

Cách xử lý: Ở terminal chạy:

openspec status
openspec list

Hoặc trong Claude hỏi:

Hãy đọc thư mục openspec/changes và cho tôi biết change nào đang mở, change nào có vẻ đã xong.

11. Checklist sử dụng hằng ngày

Mỗi khi làm một tính năng mới, hãy đi theo checklist này:

Đã làm? Việc cần kiểm tra
☐ Đã mở terminal đúng thư mục dự án.
☐ Đã chạy Claude CLI trong thư mục dự án.
☐ Nếu chưa rõ dự án, đã dùng /opsx:explore.
☐ Đã dùng /opsx:propose cho thay đổi lớn.
☐ Đã đọc lại proposal/design/tasks trước khi code.
☐ Đã dùng /opsx:apply sau khi kế hoạch đúng.
☐ Đã yêu cầu Claude chạy test/lint/build nếu có.
☐ Đã dùng /opsx:verify nếu workflow hỗ trợ.
☐ Đã dùng /opsx:archive khi hoàn tất.
Quy tắc vàng: Việc nhỏ có thể nhờ Claude sửa trực tiếp. Việc lớn nên đi qua OpenSpec để có kế hoạch, task và lịch sử rõ ràng.
Tài liệu HTML tự chứa, có thể mở trực tiếp bằng trình duyệt. Dành cho người dùng Claude CLI muốn dùng OpenSpec an toàn và dễ hiểu hơn.
